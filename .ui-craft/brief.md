# FlowDesk 设计上下文（brief）

> 本文件是跨会话的设计上下文入口，配合 `tokens.md` 使用。
> **token 数值的唯一真源始终是 `frontend/src/styles/tokens.css`**，本目录只记决定与理由，不复制数值。
> 做任何页面前先读本文件；第 6 节的 learned constraints 与 `frontend/AGENTS.md` 的硬规则同级生效。

## 1. 产品身份

FlowDesk，企业工单协作平台。核心闭环：员工提交请求 → IT 支持领取处理 → 员工确认解决。
当前处于求职 MVP 阶段，前端只做支撑核心流程所需的页面。

## 2. 受众与语言

- 受众：企业内部员工、IT 支持人员、系统管理员。**不是**外部客户，**不是**营销访客。
- 语言：**product language**。写"下一步该做什么"，不写宣传语；不堆形容词，不用"强大的""一站式"这类词。
- 读屏与键盘可达性是基线：表单可 Tab 走完、Enter 提交、焦点可见。

## 3. 设计意图

克制、可信、信息优先。单强调色（项目蓝），90% 中性色。不做装饰性视觉：
不用渐变铺满、不用发光、不用装饰性大圆、不用彩色胶囊表达趋势。

界面要传达"这件事现在到哪一步、接下来谁做什么"——这是产品本身的价值主张，
也是页面唯一值得花强调色预算的地方。

## 4. 边界（与 `frontend/AGENTS.md` 一致，不在此重复硬规则）

- `tokens.css` 是设计 token 唯一真源；`var-override.scss` 是颜色字面量唯一来源。
- Element Plus 只通过 `tokens.css` 末尾的 `--el-*` 映射改外观，不用 `:deep()`。
- Access Token 只在 Pinia 内存；刷新走 HttpOnly Refresh Cookie；权限只用于界面显隐。
- 不引入新依赖；不改后端接口契约。

## 6. Learned constraints

这些是用户对本项目设计产出的明确纠正，覆盖 ui-craft 的默认值；每条都带 why，以便泛化。
它们**不覆盖**无障碍与正确性地板。

- **禁止以"语义正确、状态齐全"的通用布局交付。**
  why：一次登录页重做把 recipe-auth 的禁止项全部满足了（tinted 中性面板、384px 表单列、
  统一 401 提示、无必填星号），但 craft-intent 的必做项一个没做——没写 Craft Read、
  没定 variance、没选 signature。产物被评价为"只是简单、正常布局，没有什么独特的审美设计"。
  结论：负向禁列只能保证"不像 AI 生成的"，不能保证"像被设计过"。

- **每个页面必须有且仅有一个能一句话指认的 signature。**
  why：没有 signature 时注意力平均分配，页面读起来是模板；有两个时强调色预算被摊薄，
  读起来是拼贴。

- **三个首选反射必须被排除：50/50 对称双栏、"eyebrow + 标题 + 灰色小字"堆叠、胶囊标签堆角色。**
  why：在没有品牌方向输入时，这三样是模型的默认落点，与 FlowDesk 这个产品无关。
  它们不是错误，是"没有做决定"的证据。

- **刻度不够时先往 `tokens.css` 加刻度再引用，禁止在页面里写死数值。**
  why：`tokens.css` 头部早已有此约定，但 `main.css` 实际出现了 `0.18em`、`0.08em`
  两处硬编码字距——说明"只有约定、没有刻度"时约定必然被绕过。已补 `--fd-tracking-*`
  与 `--fd-space-10/-11` 等刻度。

- **token 必须保留"紧—松"对比轴，不允许把所有相邻刻度取整成同一步长。**
  why：间距刻度原先几乎是线性 4px 递增，相邻档只差 4–8px，导致任何构图都落在同一节奏里，
  成品均匀而平淡。已补 `--fd-space-hairline`（2px 贴合）与 `--fd-space-10/-11`（64/80 分区）。

- **登录后页面必须使用统一应用壳：顶栏、权限侧栏、面包屑条、主体内容四层职责分离。**
  why：首页首版把业务入口留在顶栏，又在页面内部拼出权限侧栏，导航、身份与内容的职责互相重叠。
  后续受保护页面都应复用同一壳层；顶栏只放品牌与账户，左栏只放按权限生成的入口，
  面包屑只表达当前位置，页面组件只负责自己的业务内容。
- **外壳版式于 2026-09-21 按用户指示对齐对照项目，边界随之明确**：顶栏是**整幅通栏**，
  品牌位固定占侧栏那一列（竖线在顶栏内延续），账户区在右且**搜索位也在右侧**（用户同日二次调整）；
  侧栏**底色占满整列高度**、导航 sticky 在顶栏之下；面包屑的层级见下一条。用户在当次确认：
  搜索位**保留但明确禁用**（后端没有检索接口，不用可点击的假输入框冒充），顶栏**不要**预警铃铛。
  why：这条是对上一版的收窄——"顶栏只放品牌与账户"仍然成立，前提是把"账户"理解为
  "当前身份能做什么"（搜索入口、全屏、账号菜单），而不是再塞业务入口。
- **面包屑按侧栏层级显示：首页 / 一级栏目 / 页面（2026-09-21 用户确认）。**
  栏目名与侧栏共用 `constants/authorization.ts` 的同一份声明；栏目是容器、没有目标页，
  所以不做成可点击的块，只用浅一档字色；页面下的子路由（工单详情、用户详情）补出可点回
  列表页的上一级；不在导航声明里的路由（403、404）退回「首页 / 当前页」。每一级仍各自成块、
  当前级用主色浅底。
  why：曾实现成"只有首页 + 当前页"两级，用户在"系统管理"下点用户管理再点分类管理时，
  "用户管理"被"分类管理"顶掉——他要的是栏目那一级稳定不动。**同级切换只换末级是面包屑的
  正常语义**；将来若要"每访问一个页面就多一条"，那是标签栏（TagsView）而不是面包屑，
  必须单独确认，不要往面包屑里塞访问历史。
- **侧栏内部只允许有一个选中标记。** 侧栏选中态是 FlowDesk 自己的左侧竖条 + 浅底，
  分组标题在"组内有当前位置"时只变字色，不再重复出竖条或浅底。
  why：两处同时出选中态，"我在哪"就会有两个答案，强调色预算也被摊薄。

## 7. signature 候选（按 surface 归类，每页选一个）

**Auth（登录、403、404）**

1. Panel proof asset —— 一条真实工单时间线片段，或一句署名引语（二选一，不要都上）
2. Trust footer line —— 合规 / 数据位置，三级文字，落在面板底部
3. 领域化欢迎语 —— 动词绑定产品流程，不用"欢迎回来"这类通用填充
4. Real provider marks —— 本项目无 SSO，不适用
5. 面板母题 —— 极简 SVG，只出现在 tinted 面板上

**Product（首页、工单列表/详情、管理端）**

1. 自定义空态母题（复用 `EmptyState.vue`，母题与工单领域相关）
2. 全站一致的导航选中指示（左侧条 / 药丸 / 圆点，只能选一种并贯穿）
3. 工单流程阶段标记（提交 → 处理 → 确认），承担该页唯一强调色落点
4. 主表格行 hover（轻微抬起 + 阴影，只用于主表格）
5. 键盘提示（`/` 聚焦搜索、`⌘K`），在有搜索或快捷动作时使用

  在窄窗口里过一眼。
