## 3. 已确认方向与暂定尺度

**已确认**：用户喜欢 `01`、`02` 的业务后台风格，认可 Help Scout 和 Freshservice 参考；明确不满意 `03`。管理列表以 `02` 为主参考，`01` 补充工具栏。工单列表与详情分别以 `04`、`05` 为结构参考，等相应业务阶段启动后再实施。

**暂定尺度**：下面数字是首轮打样建议，不是对参考图的精确测量，也不冒充用户逐项认可。先沿用项目蓝和浅色企业后台风格，优先修比例、密度、分区。用户看打样后可调整。

- 管理列表主体跟随可用宽度，桌面左右留 20–24px；不得继续被 70rem 居中上限限制。窄屏有单独响应式策略。
- 筛选区与数据区分开；数据区包含操作栏、表格、分页。页面标题保持简短，不制造大型欢迎区。
- 正文约 14px，辅助文字 12–13px，控件高度约 32–36px，表格行高约 44–48px。全部落实为 token 或组件标准尺寸，不在每页写硬编码。
- 操作清楚可识别：主动作突出，次动作克制；行内常用动作优先图标配文字，低频动作可收进更多。不同页面按实际操作数量选择，不机械要求所有行都同样布局。
- 白底、中性背景、轻边界或轻阴影，减少大圆角与多层套卡；不复制参考图中的彩色批量按钮堆叠。
- 保留侧栏选中态唯一标记；可使用现有统一图标库改善扫描。不要添加不存在的导航功能。
- 删除面向用户的“后端最终裁决”“接口契约”“token”等实现说明；保护原因可以用用户能理解的文字解释。
- 数据少时保持合理表体空间，但不强制撑满整屏。不能用添加虚构数据掩盖布局问题。

## 4. 已发现问题与旧规则冲突

当前证据：`main.css` 的 `.page` 使用居中网格，`.admin-page .page__card` 使用 `min(--fd-page-wide-max,100%)`；`tokens.css` 中该变量是 70rem；`AppPage.vue` 无条件用一张 `.page__card` 包住所有内容；`UserListView.vue` 多处使用 small 尺寸，description 含技术说明。`03` 展现了对应的问题。

本轮优先级：最新用户反馈与本文的明确方向 > 旧管理页视觉决定。以下旧决定不再是必须延续的验收标准：

- “从52rem放宽到70rem就足够”的管理列表居中方案。
- 所有业务页面必须套一张大圆角卡片的默认结构。
- 用受保护对象标记证明页面具有审美。标记仍保留业务作用，但不能替代版式验收。
- 为了“独特性”强行增加布局突破、装饰、签名元素。实际工作效率和参考图匹配优先；signature 可以是与业务相符的结构决定，不要求装饰。

保留：认证、安全、权限、六种状态、token 唯一真源、错误码映射、现有接口、必要的可访问性。修改上述旧视觉约定时同步相关文档，不能暗中绕开规则或降低 lint。
