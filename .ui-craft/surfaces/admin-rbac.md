# 管理端页面（`frontend/src/views/admin/`）

## 用户管理页当前打样（2026-09-27 至 28）

本节取代用户页旧70rem居中大卡片与纯图标操作；下文其他方案是历史记录，其他四页未推广。

- Craft Read：内部系统管理员的业务列表，product 语言，项目蓝，variance 4；signature 是职责分离的独立筛选区与宽数据区。正向视觉声明只做这一处分区，保护标记仍是业务提示。
- AppPage list 模式使用工作区宽度与简短标题；数据区包含工具栏、表格、分页。默认 card 调用兼容。控件恢复默认尺寸，行操作图标配文字；角色授权入口按 RBAC_MANAGE 显隐。
- 长标识省略配 tooltip；窄屏整表内部滚动，不用固定两端列挤占可见区域；分页只显示总数、页码与前后页。
- 参照：02 借宽度和分区，不借额外批量功能；01 借工具栏节奏，不借多色按钮；04 借数据扫描方式，不借工单字段。
- 易平淡的三个默认选择：居中大卡、标题说明堆叠、纯图标动作。本轮均移除。三抄测试依赖实际业务：零角色明确无业务权限；管理员保护原因；USER_MANAGE 与 RBAC_MANAGE 分离的入口显隐。
- 六态仍复用原容器与权限守卫；截图、实跑证据及限制见 `../reviews/2026-09-27-admin-redesign/report.md`。用户视觉认可待反馈，不能据此宣告 RBAC 阶段收口。

> **2026-09-27 视觉反馈更新**：下文保留历史设计与实现记录，不是此次改版目标。用户明确不认可当前居中窄面板效果；70rem宽度上限、整页大卡片及以保护标记证明审美的旧方案由 `../frontend-redesign-handoff.md` 取代。新会话先查看 `../references/` 实图，首轮只打样用户管理页。业务保护、接口和六态记录仍可复用；实施后同步本文件最终决定。

## 1. Craft Read（组合层，写代码之前）

`admin data surfaces for 系统管理员（内部运维视角），product 语言，项目蓝单强调色，variance 4，signature bet：受保护对象标记（.protected-mark）贯穿用户 / 角色 / 权限三张表。`

- **DESIGN_VARIANCE = 4**，唯一一处布局突破：**标识锚点列**——登录名、角色编码、权限编码用等宽族做首列并 `fixed="left"`，
  窄屏横向滚动时主体身份不丢；容器同时从业务页的 52rem 放宽到 70rem（`--fd-page-wide-max`），
  让首列与操作列落在两端而不挤压中间内容。
- **one signature bet**：受保护对象标记。FlowDesk 有三条真实保护不变量（`SYSTEM_ADMIN` 不可删除、
  `RBAC_MANAGE` 不可删除、最后一个启用管理员不可停用或移除角色），三张表用同一枚标记说明"为什么这行不能动"。
  同类后台的默认产物是"所有行平等、为什么删不掉只能从灰按钮猜"。
- **本轮唯一一次正向视觉声明**：**一枚跨页一致的标记**（锁形图标 + 中性底色小标记）。
  它必须存在于这个产品，因为保护规则是产品语义的一部分，而不是通用后台的装饰。
- **参照物（3）**：
  1. GitHub Settings → Members/Teams：借"表格 + 右侧行内动作 + 顶部唯一主操作"的克制节奏；不借其无分页的无限列表。
  2. Linear Settings → Members：借"标识符用等宽、状态用点不用胶囊"；不借其命令面板式筛选（本项目没有该基础设施）。
  3. `kailong321200875/vue-element-plus-admin`（仓库既有锚，mini 分支）：借"查询表单 + 表格 + 分页"的三段节奏；不借演示性密集卡片网格与多套布局切换。
- **最容易平淡的三个默认选择**：① 50/50 双栏（筛选左、说明右）；② 每行堆 4 个文字按钮；③ 状态用彩色胶囊。
  **本轮放弃的是 ①**：工具带做成"左侧筛选控件组 + 右侧唯一主操作"的非对称一带，页面不分左右两栏。
  ②选择了收敛方案：每行两个可见动作 + 一个「更多」菜单承载低频动作；③用"点 + 文字"。
- **三抄测试**（同类别另一个产品不能原样抄走的 3 个决定）：
  1. 受保护对象标记指向的是"最后一个启用管理员"这类本产品独有的不变量；
  2. 两组授权页用**关系行**（主体 — 关系轴 — 客体 — 审计）而不是数据表，与工单时间线同源；
  3. 用户行的角色集合**允许为空**并写明"无业务权限"——零角色是本项目 2026-09-22 确认的合法终态，
     同类系统的默认产物是"至少一个角色"的强制校验。
- **缩略图测试**：眯眼看首屏，第一落点是主操作（新建用户 / 新建角色）与表格首列；**强调色计数**：首屏强调色出现在面包屑当前位置、侧栏选中条、主操作按钮与分页当前页，≤5 处。

## 2. 六态落点（五个页面一致）

| 状态 | 落点 |
| --- | --- |
| loading | `AdminListPanel` 的 `el-skeleton` 骨架（与表体同高），不闪空白 |
| empty | 复用 `EmptyState`，区分"没有筛选结果"与"还没有数据"两种文案 |
| error | `AdminListPanel` 的行内 `role="alert"` 面板 + 原位重试；文案走 `describeError` 稳定错误码映射 |
| disabled | 提交中按钮 loading；受保护对象（`SYSTEM_ADMIN`、`RBAC_MANAGE`、`SYSTEM_ADMIN` 的 `RBAC_MANAGE` 关系）的行内撤销 / 删除按钮禁用并给出原因 |
| 无权限 | 路由 `meta.permission`（`RBAC_MANAGE` / `USER_MANAGE`）决定入口显隐与是否跳 `/403`；后端仍是最终边界 |
| 窄屏 | ≤52rem：工具带换行、筛选控件占满宽度、关系行竖排并隐藏关系轴、分页居中 |

## 3. 契约与落层决定

- 接口：`docs/api-design.md` 8.2（`/fd/v1/users`）与 8.2.1（`/fd/v1/admin/**`）。
- `api/` 保持扁平：新增 `api/rbac.ts`（四组 RBAC 资源）与 `api/users.ts`（账号管理），不建 `api/core/`。
- 两组授权一律走批量增量端点（一个主体 × 多个客体），界面**不循环单条 `POST`**；单条撤销用路径参数端点，
  清空用整批端点——这三档粒度与后端一一对应。
- 用户角色授权页的用户选择器**已改为远程检索 `GET /fd/v1/users`**（2026-09-24 用户确认）：
  12.1 的"数字 ID + 候选下拉"前提是"后端没有用户查询接口"，该前提已随 `TASK-061` 落地而失效。
- 共享件：`components/ProtectedMark.vue`（signature 标记）、`components/AdminListPanel.vue`（四态容器）、
  `views/admin/useAdminList.ts`（取数状态机 + 服务端分页）。三者都只服务这一层，故不新开顶层目录。
- 六个轴的 token 门槛由 `frontend/stylelint.config.js` 执行（`pnpm lint` 已包含），本组页面在闸门下全绿。
- 列表密度决定：三张表都**不设"创建时间"列**——列宽之和必须落在容器内，多一列就横向溢出；
  时间属审计信息，交给后续详情页，列表只保留可扫描的身份、状态与关系计数。
- 两组授权页用"关系行"列表而不是 `el-table`：授权是责任记录，不是同构数据行。

## 4. 落地时实测到的两个缺陷（都是真问题，不是风格分歧）

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| 三张表的列被压成一条（`7px` / `12px`），行高被逐字换行撑到 **353px** | `el-table` 用 `parseInt` 解析 `width` / `min-width`，`width="7rem"` 得到 `7px` | 列宽改为无单位像素常量 `COLUMN`，行高回到 49px；规则已写进 `frontend/AGENTS.md` |
| 窄屏（768px）整页横向溢出 **130px** | `.page` 是网格，表格的 min-content（固定列宽之和 840px）把自动轨道撑宽，`width: min(...)` 挡不住自动最小尺寸 | `.admin-page .page__card` 与 `.admin-panel` 加 `min-width: 0`，横向滚动交回表格自己；已加窄屏 E2E 断言"文档不横向溢出" |

两次都是**先截图肉眼发现、再用探针量测确认**（`evaluate` 读 `getBoundingClientRect` 与
`scrollWidth/clientWidth`），修复后复测通过；探针是临时文件，验证完即删除。

## 6. 2026-09-24 二次改版：对齐参考后台的视觉语言

用户提供了两张同类企业后台（若依风格）的截图，要求"按这样的审美改页面"。采用的与不采用的：

| 参考图元素 | 处置 | 理由 |
| --- | --- | --- |
| 筛选卡片：标签在控件左侧，搜索/重置贴右 | **采用** | 一行看完所有查询条件；比"纯 placeholder 的输入框排一排"更好读 |
| 工具栏按钮组（新增 / 修改 / 删除）+ 右侧图标动作 | **采用** | 对象级动作与列表级动作分开；图标按钮承载低频动作，行内不堆文字按钮 |
| 全边框表格、灰底表头、密排行（`size="small"`，行高约 40px） | **采用** | 与参考图一致的"表格就是产品"的读法；行高回到参考图区间（40–48px） |
| 状态用开关而不是"点 + 文字" | **采用** | 开关本身可操作，省掉一列文字；开关带 `aria-label`（谁的、当前什么状态） |
| 操作列图标按钮 | **采用** | 每行 2–3 个图标 + `aria-label` + tooltip；`aria-label` 同时是单测/E2E 的定位依据 |
| 分页：共 N 条 / 条页选择 / 页码 / 前往 N 页 | **采用** | Element Plus 的 `total, sizes, prev, pager, next, jumper` 在 zh-cn 下就是这套文案 |
| 多标签页导航（工作台/用户管理/…） | **不做** | `brief.md` 已确认那属于 TagsView，要单独确认；面包屑不承载访问历史 |
| 导出按钮、批量删除 | **不做** | 后端没有对应接口。角色/权限没有批量删除端点，只有授权侧有批量撤销（已用在授权页） |
| 绿「修改」+ 橙「导出」+ 红「删除」的多色按钮组 | **收敛为蓝 + 红** | 一个强调色是已确认的硬规则；蓝=主动作、红=破坏性动作已经够表达主次 |

改动落在：`main.css` 的管理端段落（`.admin-filter-card` / `.admin-filter-field` / `.admin-action-bar`）、五个页面模板与两个共享件的用法。
**受保护对象标记（signature）与关系行（授权页）都保留**：前者是 FlowDesk 独有的保护不变量，后者是"授权即责任记录"的表达，两者都不是参考图里的东西。

### 6.1 E2E 定位上的两个教训（会复发）

1. **不要把控件包在 `<label>` 里**：点标签会向被标记的控件转发一次点击，Element Plus 的 `el-select` 于是"开了又关"。筛选字段用 `<span class="admin-filter-field">` + 控件自带 `aria-label`（读屏名不丢）。
2. **点击 `el-select` 内部的 input 会被占位符挡住**（Playwright 报 "pointer events 被拦截"）：点 select 根元素，再用 `:has([aria-label="…"])` 定位所在字段。
3. 断言**批量授予**这一类写操作时，断言 HTTP 响应（状态码 + `data` 长度）比断言 3 秒后消失的提示文案可靠得多；提示文案在超时后什么都看不到。
4. E2E 中途失败会**把临时角色留在演示库里**（清理在用例末尾）。收口前必须查一次 `iam_role` 里 `E2E%` 的残留并清掉——残留会让后续运行的列表变长、掩盖真实回归。
