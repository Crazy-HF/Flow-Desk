## 1. 共同前提

- 结构沿用 2026-09-28 已验收的管理列表语言：`AppPage layout="list"` + `.admin-filter-card`
  + `.admin-data`（工具栏 / 面板 / 分页同属一个面板），控件恢复默认尺寸，表格用无单位像素列宽。
  沿用而非重造，是因为这三页要解决的是同一类问题（查一批数据、看一条数据），
  重开一套只会让同一个应用出现两种密度。
- 权限只用于界面显隐：范围按钮按 `TICKET_VIEW_*` 出现，但后端按 `scope` 分别鉴权。
- 工单号 `FD-YYYYMMDD-NNN` 一律用等宽族 + `tabular-nums`：它是人与人之间口头/书面对齐的字符串。

## 3. DESIGN_VARIANCE = 4，每页唯一一处布局突破

- **列表**：筛选卡内部出现第二层——范围切换单独占一行，用分隔线与筛选条件隔开。
  参考后台（`02`）只有"条件 → 数据"两层；这里多出来的不是装饰，而是 `scope` 这个必填参数
  在契约里的真实地位：它决定看哪一批工单，条件决定从这批里挑哪几条。
- **新建**：优先级不是下拉，而是三个"带后果说明"的选项块横排（窄屏竖排）。
  它决定 IT 先看哪一张工单，用户需要看到后果才能选对；下拉会把后果藏起来。
- **详情**：主体 + 属性侧栏两轨（`minmax(0,1fr) 21rem`），窄屏改上下排列。
  属性栏跟正文不是同一件事：正文是问题，属性是这张单子的坐标。

## 4. 每页一个 signature bet

- **列表**：范围切换条（`01`/`02` 都没有；把它们的分页与密度借过来，把"我提交的 / 待受理 /
  我负责的 / 我参与的"这一层显式做出来）。它属于 FlowDesk 而不是任何同类系统，因为
  这四种范围是**后端契约里的必填参数**，不是前端自己分的标签页。
- **新建**：提交条（`.ticket-commit`）左半边常驻"提交编号 xxxxxxxx"，只在**这一次提交没有被
  确认**时出现，并写明"再次提交会沿用同一个提交编号和同一份内容，不会重复建单"。
  同类系统不会这么写，因为它们没有"创建前不存在可校验版本、只能靠幂等键防重"这条约束；
  把键显示出来是让用户敢于重试的唯一办法。
- **详情**：时间线脊（`.ticket-timeline__item::before` 竖线 + 节点圆点），
  记录按 `sequenceNo` 正序追加。借 Help Scout 的"一条会话一条线"，不借它的标签栏与通知数。

## 5. 本轮唯一一次"正向视觉声明"

**工单编号被当作身份锚点排版**：列表主列是"标题在上、编号在下"的等宽小字，
详情页顶部是 `--fd-font-size-md` 等宽编号 + 状态点 + 优先级点组成的标识条。

为什么这个产品需要它：工单号是唯一会被写进聊天、邮件和电话里的字符串，
而标题是给人读的。把两者放在同一个格子里的上下两层，读的时候一次就拿到"这是什么问题"和"怎么报它"。

## 7. 三个最容易让它变平淡的默认选择，本轮放弃了哪一个

1. **范围做成左边一条窄侧栏**（Help Scout 的样子）。放弃：工作区已经很宽，
   再切一条 200px 侧栏会把表格挤窄，而范围只有 3～4 项，一行就放得下。
2. **优先级做成下拉**。放弃（改成效-果并列的三个选项）。
3. **详情做成"描述卡 + 时间线卡 + 属性卡"三张等宽竖排卡**。放弃（改为主轨 + 侧栏两轨）。

## 8. 三抄测试（同类别另一个产品不能原样抄走的决定）

1. **范围切换条直接对应后端必填的 `scope`**，并且队列范围下**主动隐藏状态筛选**——
   因为后端在队列上固定 `status=PENDING`，留着它只会筛出空列表。别的产品抄不走，
   因为这是 FlowDesk 契约的形状。
2. **提交编号在界面上可见**，且"改动内容就换编号"。别的工单系统没有这条防重规则，
   也就没有这个界面元素。
3. **无权与不存在合并成同一种解释**（同一个 404），界面文案明确写"无法确认是哪种情况"，
   而不是猜"大概是没有权限"。这是契约里的安全决定，不是文案风格。
