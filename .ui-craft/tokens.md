# FlowDesk token 决定记录

> **数值不在这里。** 唯一真源是 `frontend/src/styles/tokens.css`。
> 本文件只记录"为什么这样定"，以及新增刻度时必须遵守的判断。改 token 前先读这里。

## 三层来源（不要混用）

| 层 | 位置 | 负责 |
| --- | --- | --- |
| 颜色字面量 | `frontend/src/styles/element/var-override.scss` | 品牌色与语义色的唯一字面量；EP 的 light-x / dark-2 由 SCSS 编译期计算 |
| 结构与刻度 | `frontend/src/styles/tokens.css` 的 `--fd-*` | 颜色引用、间距、字号、字距、圆角、阴影、动效、布局尺度 |
| Element Plus 映射 | `frontend/src/styles/tokens.css` 末尾的 `--el-*` | 让 EP 组件跟随项目 token；不写 `:deep()` |

`tokens.css` 必须在 `element-plus` 样式之后引入，否则 `--el-*` 覆盖不生效。

## 已确认的决定与理由

### 1. 间距必须保留"紧—松"对比轴

- **决定**：保留 2px 的贴合档（`--fd-space-hairline`），并在 48px 之上补 64 / 80 的分区档。
- **理由**：原先刻度几乎是线性 4px 递增（4/8/12/16/20/24/32/40/48），相邻档只差 4–8px。
  作者无论怎么选都落在同一节奏里，成品必然均匀、平淡。刻度要提供的是**对比**，不是更多档位。
- **推论**：`hairline` 只用于把相关信息贴合（标签↔值、数字↔单位、图标↔文字）；
  `space-10/11` 只用于页面级分区之间。**中间档不得替代这两端**，否则对比轴重新塌陷。

### 2. 字号按"角色"记，不按"大小"记

- **决定**：补 `--fd-font-size-display`（视图主视觉文字，每页最多一处）与
  `--fd-font-size-2xl`（首屏展示上限）。
- **理由**：原先 28px 之上直接跳到 40px，且 40px 被写死在全局 `h1` 的 `clamp()` 里——
  真正需要展示级的地方没有刻度可用，而每个业务页标题都拿到了 40px，层级是倒的。
- **推论**：全局 `h1` 的上限改用 `--fd-font-size-display`；展示级字号必须配
  `--fd-line-height-display` 与 `--fd-tracking-tight`，否则 44px 配 1.3 行高会上下散开。

### 3. 字距是"字号的对策"，不是装饰

- **决定**：新增 `--fd-tracking-tight / -base / -wide / -label` 四档。
- **理由**：此前**根本没有字距刻度**，结果 `main.css` 里出现 `0.18em` 与 `0.08em` 两处硬编码——
  证明"只有约定、没有刻度"时约定必然被绕过。
- **推论**：>28px 收紧，≤13px 放宽；`--fd-tracking-label` 是唯一允许全大写的档位。
  **禁止给品牌文字加宽字距来假装 logo**，那是模板感的来源；品牌位需要真正的标记。

### 4. 圆角每档绑定用途

- **决定**：`xs` 角标 / `sm` 输入类控件 / `md` 按钮与次级容器 / `lg` 卡片与对话框 /
  `xl` 页面级大容器。
- **理由**：原先只写了"按层级区分"，没有用途契约，实际出现品牌方块、输入框、按钮
  共用同一档的情况——三种元素撞在同一档，层级就读不出来。
- **推论**：新增元素时先说明它属于哪一类，再取对应档，不允许"随手取一档"。

### 5. 阴影绑定用途，三级之外不再新增

`sm` 静止的次级容器 / `md` 抬起的卡片与 hover / `lg` 页面级容器与对话框（一屏最多一处）。

### 6. 数字与编号有独立字体族

- **决定**：新增 `--fd-font-family-mono`（系统等宽栈 + 中文回退），不新增依赖。
- **理由**：本产品最有辨识度的内容是工单号、时间、状态。原先只有一句"数字加 tabular-nums"
  的约定，没有可承载编号的字体族。
- **推论**：工单号、时间戳、指标数值优先用等宽族；中文回退不可省，否则 Windows 上掉到衬线。

### 7. Element Plus 只映射结构类变量

映射字色、描边、圆角、底色、字体、动效时长与控件尺寸（`--el-component-size*`）。
**颜色色阶不在这里声明**——`--el-color-primary` 及其 light-x / dark-2 由 SCSS 编译期写入，
在这里重复声明会与 `var(--fd-color-primary)` 形成循环引用。

### 8. 外壳的结构常量进 token，不留魔法数字

- **决定**：新增 `--fd-shell-header-height`（顶栏高度）与 `--fd-shell-search-width`（顶栏搜索位宽度）；
  同时**删除** `--fd-header-padding-y`。
- **理由**：顶栏高度被至少两处引用（顶栏自身、侧栏导航 sticky 的 `top`），写死就会在某一处失配；
  搜索位宽度由内容决定（图标 + 两字标签 + 两侧留白），窄屏整块隐藏。两者都是"外壳独有的结构常量"，
  不是可以复用的间距刻度，所以单独命名，不塞进 `--fd-space-*`。
- **删除的理由**：顶栏从"内边距撑高"改为"固定高度 + 垂直居中"后，`--fd-header-padding-y`
  只剩定义处一个引用。**只在定义处出现的 token 应当删除**，否则它会诱使后来者拿它去凑高度。
- **撤回的刻度**：曾为"面包屑通栏条"加过 `--fd-shell-breadcrumb-height`；面包屑按用户指示回退到
  "内边距撑高"的原有实现后，该 token 随之删除——同一原则：不留只在定义处出现的刻度。
- **推论**：侧栏行高继续复用 `--fd-control-size-lg`（触控目标下限），不为对照项目的 50px 另开刻度。

## 改 token 时的检查顺序

1. 这个值真的需要成为刻度吗？一次性特例说明构图没想清楚，不要往 token 里塞。
2. 新刻度是否强化了对比轴（紧的一侧 / 松的一侧），还是又插了一个中间档？
3. 改动既有取值前，先统计 `main.css` 里的引用处数与影响面（含 `--el-*` 的连带影响），
   并准备截图核对——token 改值会同时影响所有已有页面。
4. 改完必须跑 `pnpm typecheck` / `pnpm lint` / `pnpm build`，并截图核对登录页与首页。
