## 第一阶段：可运行样板，等待一次集中视觉确认

1. 截取旧 FlowDesk 的壳层、首页、用户管理同视口截图，与 `06`/`07` 做差异表；从现有代码和契约确定哪些字段/动作真实存在。
2. 重铸应用壳及用户管理页，使它们在 1440×900、1920×1080 的首屏比例、侧栏/双层顶栏、筛选/数据区、控件、表格与分页上接近 `06`/`07`。窄屏 375×812 要可用。首页用 FlowDesk 真实内容适配 `06` 的层级，不能复制“项目矩阵/能力地图”等宣传内容，也不添加虚构指标。
3. 做两项右侧抽屉**样板**：从用户管理行的“分配角色”打开用户角色抽屉；从角色管理行的“分配权限”打开角色权限抽屉。进入时带入当前对象、显示已有授权与可选项；提供加载、错误、无选项、无权限、保存中、保存成功、取消与窄屏状态。保存使用现有接口与并发/保护规则；关闭后刷新关联数据且保持原列表筛选与页码。保留现有 `UserRoleGrantView`、`RolePermissionGrantView` 路由与深链可达性；在用户确认抽屉效果前，不删除旧页面。
4. 工单详情做同一视觉语言的样板：保留编号/状态/负责人/下一步动作、时间线、附件和关联。若依截图没有同构工单详情，不把它强行改成用户列表。
5. 产出样板截图、浏览器操作证据和差异表，重点报告两种分配抽屉相对现有独立页的可用性与风险。**样板交给用户集中确认一次；确认前不推广到全站。**等待期间可继续做只读梳理及测试准备。

## 不可破坏的行为

- Access Token 仅在 Pinia 内存；Refresh Cookie、401 协调、错误码映射和后端最终鉴权不变。
- 工单详情继续使用服务端 `allowedActions`，保持 `version` 回写、冲突刷新、404 不泄漏、时间线顺序和附件授权代理。
- 管理性交接、受保护角色及授权约束完整保留；不能因抽屉新入口绕过旧入口的业务保护。
- 各类页面保留 loading / empty / error / disabled / 无权限 / 窄屏；表格可局部滚动，整页不可横向溢出。按钮和抽屉必须键盘可达、焦点可见、关闭后焦点回到触发入口。
- 不改后端、数据库迁移、API 参数或业务规则，不引入若依多租户、动态菜单、代码生成等能力。
